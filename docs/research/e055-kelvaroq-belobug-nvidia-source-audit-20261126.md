## P0: NVIDIA barrier bug already present in our original source

1. [Belobug issue #13](https://github.com/Belobug/VIctory-Belobug-AMD/issues/13) documents an RTX 5070 Ti with **D3D12 debug-layer ID 523**, command-list close `0x80070057`: a state transition used flags not legal on the actual host texture. The affected code sanitized *wanted* state, not the tracked *before* state.
2. [Belobug PR #449](https://github.com/Belobug/VIctory-Belobug-AMD/pull/449), exact head **`b9251915fb5808ebd7212a90b1bcd68109d3e86a`**, fixes both sides with `legal_state`, skips equal canonical transitions. Belobug's author reported an AMD RX 7900 XT black-world scene became visible after the barrier patch, but that is different hardware and does not prove our RTX5090 issue has the same cause. The RTX5070 Ti tester's own initial state-fix progressed to another `E_INVALIDARG`, so this is **not** guaranteed to fix all crashes.
3. VIctory-W `main` exactly **`63bcca43c6a00a758510398fa43096ce7e4f7df0`**, `crates/victory-gpu/src/list.rs::host_barrier`: `second: 0xffff_ffff | (u64::from(before) << 32)` remains unsanitized, while `last` uses `crate::host::legal_state(&texture, wanted)`. Its `host::legal_for(flags,state)` already masks resource-invalid RTV/UAV/DSV/SRV bits, providing a pure, reusable implementation.
4. [Isolated VIctory-W E-056 draft PR #7](https://github.com/JohnTWillemsen/VIctory-W/pull/7), against **PR #5**, not main: optional `E056_PATCH=1` only in a disposable six-PR reconstruction, guarded exact-preimage source edit `scripts/research/e056-legal-barrier-port.sh`. A pure host-state canonicalizer is tested for preserving legal transitions, discarding equal-after-sanitization transitions and rejecting illegal state bits. Four synthetic Windows tests, no title data. [E-056 CI 45934535695](https://github.com/JohnTWillemsen/VIctory-W/actions/runs/45934535695): source preimage guard **SUCCESS**, hosted Windows still pending when documented. **No claim of runtime/render fix.**

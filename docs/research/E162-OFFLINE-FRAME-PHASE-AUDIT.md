# E162 — offline phase analysis of existing RTX5090 logs

The NVIDIA E159 source meter already emits fixed numeric FPS-window fields for total CPU preparation, its title-memory copy and texture refresh subdivisions, draw count, and pipeline-making count. The [E141 reporter](../../scripts/research/owner-nvidia-perf-audit.ps1) aggregates total CPU preparation but discards those subfields. E161's same-executable DXGI ON and OFF comparison left severe five-window low-FPS phases unexplained.

This new [offline PowerShell script](../../scripts/research/owner-nvidia-frame-phase-audit.ps1) reads *existing* owner E127 run logs only, never launches the game, and writes just E162-anonymous-phase-summary.zip under a distinct run-specific folder. It reads up to 6 logs, 256 MiB each, 250,000 lines each. It outputs no file names, paths, raw lines, assets, timestamps or strings extracted from log text: only allowlisted fixed numeric fields and an existing anonymous E127 run ID. A fail-closed Windows PS5.1 synthetic fixture tests a fake private path, two slow scene-like windows, one fast scene-like window, and an excluded non-scene window.

Thresholds: scene-like >=100 draws/frame, slow scene-like <=10 FPS, fast scene-like >=20 FPS. Aggregates are medians of multi-second meter windows, NOT individual-frame 1% lows, proven GPU utilization, measured pipeline compilation time, or causal bottleneck attribution. The residual CPU other time is clamped total-minus-copies-minus-textures, not a function-specific cost. Pipeline being-made count is a sampled queue size, not a duration.

## What is observed and what is only reported

- **It targets NVIDIA**: maintainer README reports prologue **~10 rendered fps** typical / **7–8 fps** in heavy 4K scenes on **RTX 5080**; an external-to-maintainer, still self-reported **36m46s** no-crash test on **RTX 4090** at 1440p, ~10 mean FPS. It is not an AMD-only repo, and *we have not run this title or independent performance tests on owner's 5090*. Original source: [README status](https://github.com/stellarr-studio/kelvaroq/blob/e062a82e04853bbcae281d166980e0a9b65c975a/README.md).
- **Mixed NVIDIA results:** third-party user [RTX 5070 report #11](https://github.com/stellarr-studio/kelvaroq/issues/11) says **2.3–3.2 fps** in a dark/unlit room with missing HUD letters, worse than a tested fxceless fork on their own card; [RTX 4060 #19](https://github.com/stellarr-studio/kelvaroq/issues/19) says `VICTORY_WAVE64_PAIRED=1` reduced refused compute pipelines **6→1** but was slower and one of two runs crashed; [RTX 5070 Ti #22](https://github.com/stellarr-studio/kelvaroq/issues/22) reports synthetic native GPU **229 shader passed, 3 ignored; GPU 273 passed, 17 ignored**, plus separate paired-wave readbacks. User reports are useful *leads*, not automatically audited reproducible results.
- **Current upstream checks red because of formatting**: [CI 45872242111](https://github.com/stellarr-studio/kelvaroq/actions/runs/45872242111), `cargo +stable fmt --all -- --check` stopped on Rustfmt diffs. **No later Clippy, test, or release build was executed in that CI job.** Therefore this red check neither proves runtime broken nor validates its latest native code.
- **Native DXR marketing vs public-source evidence**: latest README says native DXR works in an internal test engine, but publicly committed [`0056-raytracing.patch`](https://github.com/stellarr-studio/kelvaroq/blob/e062a82e04853bbcae281d166980e0a9b65c975a/native/patches/0056-raytracing.patch) improves **guest BVH memory residency, fault handling and translated traversal** and explicitly explains that mapping guest structures to native DXR requires *additional recovered geometry/instance/hit semantics*. This patch does not contain D3D12 `BuildRaytracingAccelerationStructure` or `DispatchRays` calls. **Do not claim the published patch proves native DXR or merges the builder**; request an actual testable source commit and private hardware verification before relying on the claim.
- **Memory status nuanced**: public v0.2.0 source has [`0063-uma.patch`](https://github.com/stellarr-studio/kelvaroq/blob/e062a82e04853bbcae281d166980e0a9b65c975a/native/patches/0063-uma.patch), including conditional `VICTORY_UMA` and `VICTORY_UMA_POOL` code and ignored WARP/hardware tests. The README states its latest *fully functional unified-memory build* is still in testing and legacy path is being removed before its *public supported build*. We have **not proven** that enabled new memory mode is delivered, safe or faster on owner's 5090. Avoid conflating *code present in tag* with *a supported validated default*.

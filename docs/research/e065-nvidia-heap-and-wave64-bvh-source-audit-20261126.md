## Source-level conclusions

1. **BVH dispatch holdback is deliberate safety behavior, not something to disable.** [Pinned #2118 `crates/victory-gpu/src/pipeline/builder.rs`](https://github.com/Marvisak/VIctory/blob/999a8f67125865fcc0b3aa23cdc8a93b10ef9974/crates/victory-gpu/src/pipeline/builder.rs): `PIPELINES` tracks live builder pipelines; `runs` computes `all_made(states) && dropped == 0`, where a refused pipeline is `Some(false)`. The source documents memory corruption from partial BVH writes if other dispatches run, so **never force the gate open**. The private E-064 owner observations reported *53 builder pipelines, 46 made, 7 refused, dropped 0 in both graphics variants*. The seven are not individually identified by public source alone. Do not attribute all seven to wave64 without per-pipeline evidence.
2. **Specific current NVIDIA shader limitations have real semantic guards.** [Pinned #439 `crates/victory-shader/src/emit/lower.rs`](https://github.com/Marvisak/VIctory/blob/e2d3cfd50715954fb89ff462edb37a0c4395ecd0/crates/victory-shader/src/emit/lower.rs) chooses split two wave32 halves vs a console-control-flow form. Its `needs_wave64` path refuses compute groups larger than 64 threads without host 64-lane waves. It also refuses unsafe LDS + title-memory interactions and some implicit derivatives and lane-mask-as-number operations. [Pinned #439 tests](https://github.com/Marvisak/VIctory/blob/e2d3cfd50715954fb89ff462edb37a0c4395ecd0/crates/victory-shader/src/emit/mod.rs) assert the group-over-64 case fails on a target limited to 32-lane waves. Changing error handling to make such shaders 'pass' without a correct algorithm would silently produce wrong scene data.
3. **Owner-private E-064 log categorization (no shader hashes or title-derived source publicly recorded):** Baseline reported **14** shader failures (9 wave64 group larger than 64, 3 implicit-derivative sample in console flow, 2 LDS/whole-wave/lane-permute combined guard). E-056 barrier variant reported **43** failures (31 group larger than 64, 7 implicit derivatives, 3 LDS/whole-wave/lane-permute, 2 lane masks read as data). These differences **cannot be interpreted as an A/B shader regression**: different cache states, work encountered and elapsed time. Counts are aggregate only. All seven refused builder pipelines' individual shader causes **still unknown**.
4. **A deterministic diagnostic flood makes renderer investigations unnecessarily costly.** [Pinned #2628 source `descriptor/host.rs::mirror`](https://github.com/Marvisak/VIctory/blob/e2cdafe560fb6b601757a8ec921e352726e6662e/crates/victory-gpu/src/descriptor/host.rs) refuses `index >= self.count` with `return None` and logs each fresh `HIGHEST.fetch_max(index)` value. For a sequential scan it prints a warning **on almost every iteration**, even without a different kind of failure. E-064 private owner A/B produced 507,331 such warnings on **both** variants, over 100 MB per stderr log. Removing or clamping these indices would be a functional/rendering change without justification. This PR **only samples warning messages**.

No E-056 barrier or other engine fix imported.

The upstream PR3409 E085 binary was compiled from `Marvisak/VIctory` `1e25b230d6572f08e718a1df31a619bb43070481`; its `crates/victory-gpu/src/host.rs` DRED `removal_data` formats `a list stopped at command N of Total (op X)`, then `commands FROM..TO between its barriers:`, and `command I (op X): <private in-flight marker>`. It also identifies page-fault matching existing and recently freed allocations and the possibility that no DRED breadcrumb node matched a submitted VIctory list. Microsoft states DRED breadcrumbs are **approximate GPU operation completion markers**, not a guaranteed precise faulting instruction; op 0 is SETMARKER, op 6 DISPATCH, op 5 EXECUTEINDIRECT, op 3/4 DRAW. See [Microsoft DirectX DRED specification](https://microsoft.github.io/DirectX-Specs/d3d/DeviceRemovedExtendedData.html).

## Scope

[owner-e091-dred-inflight-offline.ps1](../../scripts/research/owner-e091-dred-inflight-offline.ps1) is PowerShell 5.1, **purely offline**. It reads only the existing E087 run's two expected PRIVATE stdout/stderr files, never runs GTA or checks/accesses title assets, hashes, or memory addresses outside the logs. It emits a local `E091-anonymous-inflight.zip` containing precisely one fixed `E091-anonymous-inflight.txt`: integer counts of first/last stopped-command indices and totals, **whether op was parsed**, D3D12 public op-category counts, in-flight barrier ranges and selected op categories (dispatch, draw, execute indirect, copy, marker, barrier, other), page-fault allocation **presence only** (existing vs freed), log-form diagnostic presence, and slow submission values if parseable.

It never exports raw log lines, game path, memory addresses, shader IDs, DRED marker text or GPU command payloads. An op-code is a public Direct3D enumeration only; not derived title shader content. The private log raw text remains local, not public GitHub. A page-fault marker count is not a unique page-fault event count. `no_breadcrumbs_marker_lines`, `unmatched_host_list_marker_lines` and parsed stop count are distinct. An in-flight `dispatch` count **does not prove the dispatch caused GPU loss**; neither does the last stopped op=SETMARKER.

Synthetic [Windows PowerShell 5.1 tests](../../scripts/research/test-e091-offline-dred-inflight.ps1) verify (1) parser/fixed schema, (2) two DRED stopped markers incl `op 0` presence flag, (3) barrier intervals and in-flight classification, (4) page-fault allocation context & slow submission parsing, (5) no private-looking strings in the ZIP and repeated run equality, (6) refuse missing logs. These are not GPU/title tests.

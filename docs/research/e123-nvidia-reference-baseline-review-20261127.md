# E123 — VIctory-NVIDIA: audit a real NVIDIA playability baseline before more fixes

**Status (2026-11-27 AZ): SOURCE REVIEWED, SOURCE-ONLY CI REQUESTED; USER GPU NOT TESTED. This does not assert gameplay.** Preserve the existing `VIctory-W` `main`, agent docs, all experimental PRs, and owner-local game files.

## Why change baselines

The existing E096 `Marvisak/VIctory` #3409 source candidate gave encouraging 300-second title tests, but the author later corrected their test adapter to an **AMD iGPU**, not the initially claimed RTX5070Ti. Owner E096/E108/E109 tests on an RTX5090-equipped Windows PC ended in `0x887A0005` and **never verified a selected runtime GPU, rendered world, and working controls**. The E087 supervisor checked only that `nvidia-smi` saw an RTX5090; it forced Series X and D3D12 debug by default, while NVIDIA-focused forks use different launch options. E121 PR35 CI also failed compile checks and is not a validated GPU patch. These facts warrant a new reference-first workflow, not further speculative patch stacking.

## New NVIDIA-focused candidate: pin and understand it

Repository: [trustno1-coder/VIctory-NVIDIA](https://github.com/trustno1-coder/VIctory-NVIDIA), GPL-3.0-or-later; README at HEAD `64d4931b3dd90305134512b805fc98f04119fb6e` reviewed. Current base is [foxhound](https://github.com/readmet3xt-lab/foxhound) (author credits its `02fc18a` snapshot and several earlier forks). This source tree includes NVIDIA-focused descriptor heap allocation, 32-lane shaders, renderer workarounds, explicit DXGI adapter selection, optional DLSS, saved settings and a built-in release launcher. The original upstream vendor-specific source forks and our E109 fork are **not identical**; do not assume these fixes exist in our existing branch or that a blanket merge is conflict-free.

- **Author-reported validation (not owner-verified):** Windows 11, Ryzen 7 9800X3D, RTX 5070 12 GB, 64 GB RAM, title Xbox Series v1.0.2.1, **Series X 2560x1440 DLSS Quality**, opening rooms mostly 26-30 true rendered FPS, no D3D12 device removal in measured sessions. These are not RTX5090 stability or long-game guarantees.
- **Actual graphics-device selection confirmed in source:** `crates/victory-shader/src/emit/host.rs` `hardware_adapter` enumerates hardware adapters and selects the greatest dedicated video memory unless `VICTORY_ADAPTER` matches a name; `crates/victory-gpu/src/host.rs` `Host::new` explicitly uses that adapter with `D3D12CreateDevice(&adapter)` and logs the chosen name and MB. If explicit selection fails it falls back to `D3D12CreateDevice(None)`; therefore **fail closed on absent positive RTX5090 log evidence**, not simply NVIDIA utility presence. The console emulator's reported virtual DXGI device is separate from this physical host device.
- **Launcher identity:** `scripts/play-nvidia.ps1` delegates to `scripts/play-foxhound.ps1`; release executable's built-in `victory play` also sets options from `%LOCALAPPDATA%\\victory\\victory-settings.txt`. The launcher does **not** use E087's forced Series X + debug workload unless chosen. With the script default: **Series X**, native 1440p, optional DLSS Quality if NVIDIA DLLs are installed, uncapped native frame interval, DLSS frame generation **ready but off**. Series S `-SeriesS` is supported. `VICTORY_BVH_BUILDER=1` enables unfinished native RT; keep **off** for first playability reference. The lighter renderer intentionally uses a lighting/reflection estimate; playable is not equal to native-console accurate ray tracing.
- **Different source versions with real tradeoffs:** [v2026.11.27.7](https://github.com/trustno1-coder/VIctory-NVIDIA/releases/tag/v2026.11.27.7) exactly pins commit `df2daafeb1b2170931cf7a6eddff6de254841d9c`. Its official published `victory.exe` SHA-256 is `592098184c5c16bf237701648c193f47a25c0647c82bd27495d832134b00fba5` (publisher report and GitHub release digest); earlier performance-focused version and launcher fixes. [v2026.11.27.8](https://github.com/trustno1-coder/VIctory-NVIDIA/releases/tag/v2026.11.27.8) pins `64d4931b3dd90305134512b805fc98f04119fb6e`, publisher SHA-256 `30cce7b52c903ce8f6e1fd7518076b41c8f058a5cf12e70b7468317edcf83702`; later water/lighting/controller/memory changes, **publisher explicitly warns lower FPS**. GitHub Actions source builds have their *own* hashes; do not claim they reproduce the published binaries bit-for-bit without a separate comparison.
- **Safety/reproducibility:** release executables are unsigned. On first start the built-in launcher can offer downloads of NVIDIA Streamline DLLs (or FSR/Agility if chosen/needed) and may automatically restart once after warm-up. For a first controlled A/B, prefer source-only CI, isolated folder/cache, explicit settings, deliberate decision about downloads, and one supervised runtime with allowed auto-relaunch distinguished from crash. Do **not** upload title assets, screenshots, executable, private logs, paths or derived shader blobs to public GitHub. Avoid instructing owner to bypass anti-malware protections on unverified binaries.
- **No current NVIDIA-fork CI assertion:** upstream GitHub Actions main workflow list shows mostly `needs-logs`; multiple open PR CI results are `action_required`. An official release's existence or download count is not a validated cross-machine source build. **Independent strict Windows build/tests must be done in our own isolated workflow before hardware use.**
- **Asset policy notice:** upstream's own `docs/asset-policy.md` expressly excepts a 78-KB `bcpack-tables.bin` format constant file with separate licensing. Treat that exception as upstream provenance requiring review before wholesale code import; never assume GPL applies to that binary. No title game files are checked into our E123 branch.
